## 1. 需求分析

### 1.1 典型场景

| 场景   | 说明                                       |
| ---- | ---------------------------------------- |
| 镜头选型 | 供应商 A 镜头 vs 供应商 B 镜头，同一 sensor/整机，谁解析力更好 |
| 批次抽检 | 金样（Golden Sample）vs 待测模组（DUT），判定批次一致性    |
| 调焦验证 | 同一镜头调焦前/后（或不同对焦位置）的 MTF 对比               |
| 来料对比 | 新批次镜头 vs 历史批次留存数据                        |

共性：两次拍摄（或两组历史数据）的 MTF 结果做**同口径对比**，
输出逐视场位置的差异与总体优劣结论。

### 1.2 与现有 MTF 模块的关系

**比较功能不重新计算 MTF，只消费 MTF 结果**。现有 `analyze_mtf`
（`iqtest/analysis/mtf_adapter.py`）已输出完备的结果结构：

* `metrics`：逐 ROI 的 MTF@评估频率、MTF50（判定级）、MTFnn/MTFnnP（INFO）；

* `details["curves"]`：逐 (ROI, 通道) 的完整 MTF 曲线（freq/mtf 数组）；

* `details["rois"]`：ROI 位置、所属图像、有效性；

* `details["freq_unit"]` / `unit_scale` / `gamma` / `criteria`：计算口径参数。

比较模块的输入 = 两份导出的 **MTF 结果 CSV**（A、B），
输出 = 差异分析与结论。核心算法（斜边 SFR、C++ 引擎）零改动。

> **前置依赖**：MTF/SFR 模块目前**不具备结果 CSV 导出功能**，
> 需先实现（见 §6.1）。导出在结果 Figure 上进行，此时 curves 仍在内存，
> 可顺带把 MTFa（曲线下面积，§4.1）算好写入 CSV。

## 2. 公平比较的前提（同口径校验）

MTF 是绝对量，但比较结论只在**同口径**下成立。加载 A/B 两份 CSV 时
必须做兼容性检查，不满足则阻止比较并给出明确提示：

| 检查项              | 规则                   | 不满足时                 |
| ---------------- | -------------------- | -------------------- |
| 频率单位 `freq_unit` | 必须一致                 | 报错（禁止混单位比较）          |
| 评估频率 `freq1`     | 必须一致（容差 1e-6）        | 报错                   |
| Gamma            | 必须一致                 | 报错（γ 影响 MTF 曲线形状）    |
| 测试项（指标列）         | 取两边 CSV 的**交集**供用户选择 | 仅一侧有的指标不出现在选择列表      |
| 分辨率 / 像元尺寸       | 见 §3.3               | 跨像元时给出「仅供参考」提示       |
| ROI 位置覆盖         | 见 §3.2               | 仅一侧存在的视场位置不参与比较，列表标注 |

> 数值噪声基线：项目实测同图同 ROI 重复测量的不确定度在 ±0.003
> （SFR 值）量级（见 MTF 开发文档 §13）。比较的「打平阈值」必须大于
> 噪声基线才有意义，默认取 0.01（可配置），见 §4.2。

## 3. 架构设计

### 3.1 总体方案：MTF 结果 CSV 驱动

```
  模组 A 图像 ──→ analyze_mtf ──→ MTF 结果 Figure ──→ 导出结果 CSV（A.csv）─┐
                                                                            ├─→ mtf_compare
  模组 B 图像 ──→ analyze_mtf ──→ MTF 结果 Figure ──→ 导出结果 CSV（B.csv）─┘   （校验→位置匹配→差异→评分）
                                                                                │
                                            MtfCompareResultView（视场差异图 + 对比表 + 结论横幅）
```

**为什么用 CSV 而不是会话内直接比较**：

1. 现有会话模型是「一批图像对应一个测试项」（模块互斥单选），
   两组不同模组的图像混在一个会话会破坏该假设；
2. CSV 是测试工程师最熟悉的交换格式，可直接用 Excel 打开复核，
   也便于归档到测试报告/产线数据目录；
3. 比较可以**跨时间、跨机器**进行（今天的 DUT vs 上周留存的金样 CSV），
   覆盖批次抽检/来料对比场景；
4. 比较逻辑（校验、匹配、差异、评分）与 GUI 完全解耦，可纯单元测试。

**入口**：

* MTF 结果 Figure 增加「**导出结果 CSV…**」按钮（前置功能，§6.1）；

* 主界面 **🛠 Utilities → MTF 模组比较…** 打开比较面板 → 分别载入
  CSV A / B → 选择比较测试项 → 「比较」→ 结果 Figure。

### 3.2 CSV 格式设计

单个 CSV 文件 = `#` 开头的元数据头 + 一张逐 (ROI, 通道) 的指标表。
元数据保证口径可校验；指标表即 MTF 结果 Figure 右侧指标表的完整内容，
并附加 ROI 归一化位置与 MTFa：

```csv
# LeopardIQ MTF Result CSV
# schema_version: 1
# label: LensA_SN001
# created: 2026-08-14T17:30:00
# image: SN_2-0.6_D_07_28_2026_T_16_37_32.raw
# image_width: 1920
# image_height: 1200
# freq_unit: Cycles/pixel
# freq1: 0.125
# gamma: 1.0
# pixel_size_um: 2.0
# picture_height: 1200
roi,channel,cx_norm,cy_norm,valid,mtf@0.125,mtf50,mtf30,mtf50p,mtfa
1,Y,0.502,0.487,1,0.4213,0.1821,0.3105,0.2988,0.0821
2,Y,0.083,0.092,1,0.3102,0.1211,0.2244,0.2101,0.0610
...
```

| 列                     | 说明                                                                       |
| --------------------- | ------------------------------------------------------------------------ |
| `roi`                 | ROI 编号（导出时的框选顺序）                                                         |
| `channel`             | 通道名（Y / R / G / B…）                                                      |
| `cx_norm` / `cy_norm` | ROI 中心坐标归一化到图像尺寸（0\~1），**位置匹配的唯一依据**，见 §3.3                              |
| `valid`               | 该 ROI 是否有效（引擎成功），0/1                                                     |
| `mtf@{freq}`          | MTF @ 评估频率（SFR 值，0\~1）；列名携带实际频率，比较界面显示为「MTF @ 0.125 cy/px (1/4 Nyquist)」 |
| `mtf50`               | MTF50，单位 = `freq_unit`                                                   |
| `mtf30` / `mtf50p` …  | 各 Secondary Readout（按导出时配置，动态列），频率类                                      |
| `mtfa`                | MTF 曲线下面积（0\~Nyquist 积分，导出时由内存中的 curves 计算），整体锐度度量                       |

* `label` 导出时由用户填写（默认图像文件名），显示在比较界面的
  A/B 表头与结论中；

* 指标列是**动态**的：测了什么就有什么列，比较时的可选测试项 =
  两份 CSV 指标列的交集（§4.4）；

* 元数据头缺失 `schema_version` 或关键口径字段时报明确错误；
  未知 `#` 键静默忽略（向后兼容）。

### 3.3 ROI 匹配：按视场位置（不用坐标）

公司 MTF 测试 chart 基本统一：**五个黑块**（中心一个 + 四角各一个），
ROI 取在黑块斜边上。两个模组的拍摄摆位、ROI 框选坐标**不可能一致**，
因此坐标匹配没有意义；但黑块对应的**视场位置**是稳定的——
按位置匹配即可天然对齐两次测试。

匹配规则（`mtf_compare.py` 纯函数）：

1. **分区**：用 `cx_norm` / `cy_norm` 把 ROI 分入 3×3 九宫格，
   得到位置标签：`center / top / bottom / left / right /
   corner_tl / corner_tr / corner_bl / corner_br`；
   （五黑块 chart 的实际结果 = center + 4 个 corner\_\*）
2. **配对**：同一位置标签内 A/B 配对；若同一位置有多个 ROI
   （如一个黑块框了两条斜边），按**到图像中心的归一化距离排序**
   后依次配对；
3. **兜底**：一侧多出的 ROI 不参与比较，在对比表中单独列出并标注
   「仅 A」/「仅 B」。

配对结果在比较面板中以**位置示意图**（3×3 网格，每格显示 A/B 各几个
ROI、配对几对）呈现，用户确认后再执行比较。

### 3.4 跨分辨率/跨像元处理

* 分辨率不同：不影响——`cx_norm/cy_norm` 已归一化，位置匹配天然兼容；

* 像元尺寸不同：要求两边 `pixel_size_um` 均非空，频率类指标
  （MTF50/MTFnn）统一换算为 **LP/mm** 再比较，并在结果中显著标注
  「跨像元比较，结论仅供参考」；

* SFR 类指标（MTF\@freq、MTFa）为 0\~1 无单位量，不受像元影响。

## 4. 比较指标、测试项选择与评分模型

### 4.1 逐位置差异量

对每个配对的（位置, 通道）计算所选测试项的差值：

```
Δ指标 = 指标_A − 指标_B
```

| 候选测试项                          | 来源列          | 类型            |
| ------------------------------ | ------------ | ------------- |
| MTF @ 评估频率（如 1/4 Nyquist）      | `mtf@{freq}` | SFR 类（0\~1）   |
| MTF50                          | `mtf50`      | 频率类           |
| MTFnn / MTFnnP（如 MTF30、MTF50P） | 动态 readout 列 | 频率类           |
| MTFa（曲线下面积）                    | `mtfa`       | SFR 类（0\~0.5） |

无效 ROI（`valid=0`）在任一侧即整对排除，差异表标 `—`。

### 4.2 胜负判定（tie band）

```
diff = metric_A − metric_B
|diff| ≤ tie_threshold  → 平手（TIE）
diff  > +tie_threshold  → A 胜
diff  < −tie_threshold  → B 胜
```

* 打平阈值按指标类型分别默认：频率类 0.01 cy/px 的换算值，
  SFR 类 0.01；均可在比较面板配置；必须 > 测量不确定度（±0.003）；

* 逐测试项汇总 **胜/平/负计数**（win/tie/loss）。

### 4.3 总体评分（按所选测试项，分区加权）

```
Score(模组, 测试项) = Σ_zone w_zone × mean_zone(归一化指标)
```

* **分区**：中心（center）/ 边缘（top/bottom/left/right）/ 角（corner\_\*）三类；

* **默认权重**：中心 0.4 / 边缘 0.3 / 角 0.3（可配置）；

* **归一化**：频率类除以 Nyquist（0.5 cy/px 的换算值），SFR 类原值；

* **结论横幅**（对每个所选测试项）：

  * `|Score_A − Score_B| ≤ score_tie`（默认 0.01）→ **两者相当**；

  * 否则输出优胜方 + 差距百分比 + 主要贡献区域
    （如「B 更好，优势主要在四角（ΔMTF50 = −0.04 cy/px）」）。

### 4.4 比较测试项选择（评审新增）

MTF 测试本身会同时产出多个指标（MTF50、MTF@评估频率、各 Readout、
MTFa），客户关心的点因人而异（有人看 MTF50，有人看 1/4 Nyquist 处的
SFR）。因此比较面板提供**测试项勾选区**：

* 可选项 = 两份 CSV 指标列的**交集**（列名校验同口径后）；

* 显示友好名：`mtf@0.125` →「MTF @ 0.125 cy/px (1/4 Nyquist)」，
  `mtf50` →「MTF50 (cy/px)」；

* **多选**：勾几项就比较几项，对比表每个所选测试项一组
  A / B / Δ / 胜负列；

* **主判定项**：在所选项中指定一个（默认第一个勾选项），
  顶部结论横幅按主判定项的评分给出，其余测试项的结论
  在汇总区逐项列出（如「MTF50：A 优；MTF\@1/4NY：相当」）。

### 4.5 N 款比较：基准金样模式（2026-08-17 实现）

两款以上的比较复用全部 pairwise 逻辑，规则：

* **动态槽位**：2~6 款 CSV 槽位（「＋ 添加模组 CSV 槽位」/「✕」移除），
  每槽位带「基准」单选（默认槽位 A 为基准/金样）；
* **比较方式**：基准排首位，其余各款分别与基准跑一次 pairwise
  `compare()`（§4.1~4.4 逻辑零改动），共 N−1 组结果；
  阈值/权重/测试项勾选对 N−1 组共用同一套配置；
* **匹配**：公共视场位置 = 全部 N 款都有数据的 (位置, 通道) 组
  （`match_zones_multi`），配对预览表逐位置显示各款 ROI 数与公共数；
* **判定**：每组独立给出胜负/评分结论（如基准为金样，则
  「verdict = A」表示基准优、「B」表示该款优于基准）；
  总体结论区按「基准（金样）：XXX」+「【各款 vs 基准】」逐款分块；
* **保存**：两款保存单个 CSV；N 款弹目录选择框，按
  `MTF比较_{基准}_vs_{各款}.csv` 逐款落盘 N−1 个文件；
* **局限**：只做「各款 vs 基准」，不做非基准款之间的两两比较
  （N 方全配对 = N×(N−1)/2 组，结论区会爆炸；如有需要可后续加
  汇总矩阵表）。

## 5. 结果可视化（嵌入比较对话框，2026-08-17 修订）

> 按评审意见修订：比较图表**直接嵌入比较对话框**，比较完成后立即可见，
> 不再弹独立 Figure 窗口；比较结果**不自动保存**，由
> 「保存比较结果 CSV…」按钮让用户自行决定是否落盘。

| 区域 | 内容 |
|------|------|
| 结论摘要区 | 总体结论（主判定项）+ 逐项结论 + 单边 ROI 注记 + 跨像元警示 |
| 图表测试项下拉 | 切换图表显示的测试项（默认主判定项） |
| 左：A/B 双线对比图 | **横轴 = ROI 视场位置**（中心在前，其后四角/边缘；同位置多 ROI 加 `#n`，多通道加通道名），**纵轴 = 所选测试项值**；A 实线圆点 / B 虚线方点，频率类按显示单位换算；**N 款时为 N 条折线**（基准加粗实线，其余按镜头配色轮换线型/符号） |
| 右：Δ 差异条形图 | 每位置 A−B 条形（**红 = A 优，蓝 = B 优，灰 = 平手**），叠加 ±打平阈值虚线参考线——带内差异为噪声级，带外才是真差异；零线常显；**N 款时为同一张图内每位置 N−1 根并排条形**（各款 − 基准，每根用该镜头专属颜色，与其折线同色），±tie 虚线照旧 |
| 保存按钮 | 「保存比较结果 CSV…」：用户主动触发，CSV 含口径元数据、比较配置回显（tie/权重/单位）、逐项统计与总体结论注释行、逐位置 A/B/Δ/胜负列组、仅单侧 ROI 附表尾 |

重新载入任一 CSV 后，旧比较结果失效：图表清空、保存按钮禁用。

比较结果 CSV 由 `mtf_compare.compare_result_to_csv` /
`write_compare_csv` 生成（纯函数，`compare_schema_version: 1`，
utf-8-sig 带 BOM）。

> 注：CSV 不含完整 MTF 曲线数据，故比较结果**不做曲线叠加图**。
> 若后续需要，可扩展导出功能附带曲线 CSV（长表格式：
> roi,channel,freq,mtf），列入开放问题（§9）。
